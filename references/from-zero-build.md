# From-Zero Desktop Pet Build Guide

Use this guide when the user wants a complete desktop pet or desktop companion app. Build from
assets toward interaction: clarify, provide prompts, inspect assets, create a browser preview,
then package only after user confirmation.

## 1. Confirm Product Shape

Ask only for missing product facts that cannot be inferred:

- Subject: animal, mascot, character, object, brand figure, or other companion.
- Visual style: realistic, cartoon, pixel, 3D render, hand-drawn, brand-specific, etc.
- Core interactions: idle, cursor follow, drag, click, settings, prop reaction, or custom flows.
- Target OS: Windows, macOS, or both.
- Asset availability: already supplied, generated by the user, or mixed.

Default choices when the user does not specify:

- Vue 3 + TypeScript + Tauri 2.
- Canvas renderer over regular DOM animation.
- Transparent always-on-top undecorated window.
- Solid-color MP4 action loops plus transparent PNG follow frames.
- LocalStorage for simple settings persistence.
- Chinese i18n keys first.

## 2. Prepare Asset Prompts Before Coding

Read `asset-generation.md`, then give the user prompt templates tailored to the product. Recommend
豆包 or 即梦 for generation if the user does not name another tool.

Keep prompts generic and reusable:

```text
主体：[用户的主体]
风格：[用户想要的风格]
动作：[动作或状态]
输出：[绿幕视频 / 透明 PNG 序列 / 图标]
约束：静态镜头、完整主体、无文字、无水印、无 Logo、无 UI、比例一致。
```

Ask the user to provide the generated assets before final implementation. Do not call image or
video generation models yourself.

## 3. Inspect Supplied Assets

Before writing the final renderer:

- Check file roles and names.
- Check resolution, framing, loop quality, transparency or chroma-key suitability.
- Check whether actions share consistent scale and anchor.
- Identify which issues require regeneration and which can be handled in code.

If assets are missing, create a minimal placeholder-only scaffold only when it helps the user
preview layout. Make it clear that final rendering waits for real assets.

## 4. Scaffold Project

Use the current package manager if the repo already has one. For a new app:

```powershell
npm create tauri-app@latest desktop-pet
```

Choose:

```text
Frontend: Vue
Language: TypeScript
Package manager: npm, pnpm, or the user's existing choice
```

Install dependencies and make sure the frontend can run:

```powershell
cd desktop-pet
npm install
npm run dev
```

Prefer browser preview before desktop runtime. Start desktop runtime only after the web version
has something meaningful to test.

## 7. Build the Minimal Browser Renderer

Start with one canvas and one known-good asset. Do not add all interactions before the first frame
renders.

```vue
<script setup lang="ts">
import { computed, onBeforeUnmount, onMounted, ref } from "vue";

type PetMode = "idle" | "follow" | "interact";

interface PetSettings {
  scale: number;
  enablePointerFollow: boolean;
  enableDragging: boolean;
}

const canvasRef = ref<HTMLCanvasElement | null>(null);
const mode = ref<PetMode>("idle");
const settings = ref<PetSettings>({
  scale: 80,
  enablePointerFollow: true,
  enableDragging: true
});

const canvasSize = computed(() => Math.round(320 * settings.value.scale / 100));

let animationFrame = 0;
const idleVideo = document.createElement("video");
idleVideo.src = "/videos/idle-primary.mp4";
idleVideo.muted = true;
idleVideo.loop = true;
idleVideo.playsInline = true;

const render = (): void => {
  const canvas = canvasRef.value;

  if (!canvas) {
    return;
  }

  const context = canvas.getContext("2d", { willReadFrequently: true });

  if (!context) {
    return;
  }

  context.clearRect(0, 0, canvas.width, canvas.height);
  context.drawImage(idleVideo, 0, 0, canvas.width, canvas.height);
  animationFrame = requestAnimationFrame(render);
};

onMounted(() => {
  void idleVideo.play();
  render();
});

onBeforeUnmount(() => {
  cancelAnimationFrame(animationFrame);
  idleVideo.pause();
});
</script>

<template>
  <main class="pet-root">
    <canvas
      ref="canvasRef"
      class="pet-canvas"
      :width="canvasSize"
      :height="canvasSize"
    />
  </main>
</template>

<style scoped>
.pet-root {
  width: 100vw;
  height: 100vh;
  display: grid;
  place-items: center;
  background: transparent;
}

.pet-canvas {
  width: v-bind(canvasSize + "px");
  height: v-bind(canvasSize + "px");
}
</style>
```

After this works, split asset loading and rendering into smaller functions.

## 8. Add Asset Registry

Use data definitions instead of hardcoding action branches:

```ts
type AssetKind = "video" | "follow-frame" | "image";

interface PetAction {
  id: string;
  kind: AssetKind;
  source: string;
  weight: number;
  enabled: boolean;
  canUseWatermarkMask: boolean;
}

const actions: PetAction[] = [
  {
    id: "idle-primary",
    kind: "video",
    source: "/videos/idle-primary.mp4",
    weight: 60,
    enabled: true,
    canUseWatermarkMask: true
  }
];
```

Implementation rules:

- Videos may use chroma key when they are solid-color sources.
- Transparent frame sequences are final and should be drawn directly.
- Do not lower alpha in green edge cleanup unless the pixel is confidently background.

## 9. Add Settings Persistence

Use storage as soon as controls exist:

```ts
const storageKey = "desktop-pet-settings";

const defaultSettings: PetSettings = {
  scale: 80,
  enablePointerFollow: true,
  enableDragging: true
};

const readSettings = (): PetSettings => {
  const raw = localStorage.getItem(storageKey);

  if (!raw) {
    return defaultSettings;
  }

  return {
    ...defaultSettings,
    ...(JSON.parse(raw) as Partial<PetSettings>)
  };
};

const writeSettings = (nextSettings: PetSettings): void => {
  localStorage.setItem(storageKey, JSON.stringify(nextSettings));
};
```

In production code, validate parsed values before using them.

## 10. Keep Browser Preview Working

Desktop APIs must be feature-detected so the web preview remains usable:

```ts
import { invoke } from "@tauri-apps/api/core";

interface MovePetWindowArgs {
  x: number;
  y: number;
}

const canUseTauri = (): boolean => "__TAURI_INTERNALS__" in window;

const movePetWindow = async (args: MovePetWindowArgs): Promise<void> => {
  if (!canUseTauri()) {
    return;
  }

  await invoke<void>("move_pet_window", args);
};
```

Start the dev server after implementation:

```powershell
npm run dev
```

Give the user the local URL and ask them to confirm the interaction, visual style, size, and
behavior before desktop packaging.

## 11. Add Desktop Runtime Commands

Expose OS window actions from Rust. Keep comments/log messages in Chinese when needed.

```rust
use tauri::Manager;

#[tauri::command]
fn move_pet_window(app: tauri::AppHandle, x: i32, y: i32) -> Result<(), String> {
  let window = app.get_webview_window("main").ok_or("找不到主窗口")?;

  window
    .set_position(tauri::Position::Physical(tauri::PhysicalPosition::new(x, y)))
    .map_err(|err| format!("移动窗口失败: {err}"))?;

  Ok(())
}
```

Register commands in `main`:

```rust
tauri::Builder::default()
  .invoke_handler(tauri::generate_handler![move_pet_window])
  .run(tauri::generate_context!())
  .expect("运行桌宠失败");
```

## 12. Implement Interactions

Minimum interaction order:

1. Click or pointer action: trigger a short interaction.
2. Context menu or button: open settings.
3. Close settings: restore previous pet position and size.
4. Drag: update desktop window position while pointer is down.
5. Pointer follow: move the desktop window or update follow frame target.

For follow visuals:

- Use transparent frames directly.
- Keep current follow frame fully opaque.
- Fade previous visual layer for about 180 ms.
- Stop global pointer listeners when disabled.

## 13. Settings Panel

Settings panel must be independent of pet canvas bounds:

- Open by resizing the desktop window to a panel size such as `420x520`.
- Clamp the whole window to the current monitor work area.
- Close by restoring the pet window size and previous position.
- Use i18n key `settings.title` with value `设置`.
- Keep panel controls inside one scrollable area if content exceeds height.

## 14. Performance Pass

Before packaging:

- Cap render loop around 30 fps for video actions unless motion demands more.
- Cache loaded videos and PNG frames.
- Reuse scratch canvas buffers for chroma key.
- Pause inactive videos.
- Avoid per-frame allocations in pointer-follow loops.
- Disable Rust/global pointer listeners when follow is off.

## 15. Verification

Browser preview:

```powershell
npm run dev
```

Check:

- Canvas is transparent outside the subject.
- No rectangular white, black, green, or transparent blocks.
- Transparent frames are not washed out.
- Core interactions are understandable and responsive.
- Settings persist after reload.

Wait for user confirmation before desktop packaging.

Desktop runtime:

```powershell
npm run tauri:dev
```

Check:

- Transparent window receives click, right click, drag, and follow events.
- Settings panel is fully visible near screen edges.
- Pointer leaving follow area releases quickly.
- Switching modes does not show duplicate subjects.

## 16. Package

Build frontend first:

```powershell
npm run build
```

Then package:

```powershell
npm run tauri:build
```

If Windows build memory is tight:

```powershell
$env:CARGO_BUILD_JOBS = "1"
npm run tauri:build
```

For a minimal mac-buildable source package, include:

```text
src/
src-tauri/
public/
index.html
package.json
package-lock.json or pnpm-lock.yaml
tsconfig*.json
vite.config.ts
README or short build note if the user asks for one
```

Exclude:

```text
node_modules/
dist/
src-tauri/target/
large temp folders
old installers
```

macOS native bundles must be built on macOS. Do not promise a real `.dmg` or `.app` from Windows
unless a macOS builder is available.

## 17. Common Failure Diagnosis

- Follow subject becomes transparent: app is post-processing transparent frames. Draw them
  directly.
- White, green, or transparent rectangle appears in one corner: inspect watermark mask or canvas
  clear rectangle first.
- Important edges are cropped: source asset framing or draw destination bounds are wrong.
- Desktop interactions disappear: transparent window may be ignoring cursor events, or frontend
  pointer layer is covering the canvas.
- Settings panel is clipped: panel is still constrained by pet window size or not clamped after
  resizing.
